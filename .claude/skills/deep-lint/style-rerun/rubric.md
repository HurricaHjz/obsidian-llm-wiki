# Rubric for a style re-run on the `{{STYLE}}` style

Rendered {{RENDERED}} by render-rubric.py, so section B is the live definition. The judge scores each reply by content and plainness. Length is never a verdict: a longer reply is not worse and a shorter one is not better, and nothing in this rubric is counted in words.

## A. Plain and fluent (the Identity bullet, binds every reply)
A1 plain words: an everyday word wherever it says the same as a technical one; a term that stays is explained where it first appears (unless the owner used it first).
A2 the answer first: the reply opens with what was asked (after the status line), not background or a progress line.
A3 each asked part named where it is answered, in the order asked (a sentence or a short lead the reader can follow).
A4 a claim carries its instance beside it (the file, the number, the person).
A5 one idea per sentence, each following from the last, in a table cell as in prose; no claim contradicts an earlier one.
A6 every reference names its target where it is made; no "the earlier table", "as noted above".
A7 an explanation starts with the thing explained as its subject and says what it does; a table row reads as that sentence with its label as the subject.

## Scoring
For each reply: A1–A7 each PASS / FAIL with one quoted sentence as evidence; B PASS / FAIL with the quoted sentences that break the Test (or "none"); an overall plainness verdict (readable on one pass: yes / no) and the single most damaging sentence. No word count anywhere.

Where a predecessor reply to the same question is given, one comparison line per reply: better, same or worse, and on what. "On what" means the content (each asked part answered, nothing asked left out, nothing unasked added) and the plainness (A1–A7). Never the length: a reply is not better for being shorter or worse for being longer.
